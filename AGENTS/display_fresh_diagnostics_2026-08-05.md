## 2. Состояние DSI

| Адрес | Значение | Регистр | Расшифровка |
|-------|----------|---------|-------------|
| 0x14013000 | 0x00000001 | DSI_START | bit 0 = 1 |
| 0x14013008 | 0x00000003 | DSI_INTEN | bits 0,1 включены (ошибка драйвера!) |
| 0x1401300c | 0x80001016 | DSI_INTSTA | **bit 31 = DSI_BUSY = 1** |
| 0x14013010 | 0x01000000 | DSI_CON | **bit 1 = DSI_EN = 0** (контроллер выключен!) |
| 0x14013014 | 0x00000000 | DSI_MODE_CTRL | **Command mode** (биты [1:0] = 0) |
| 0x14013018 | 0x0001023c | DSI_TXRX | 4 лосы, EXT_TE_EN=1 |
| 0x1401301c | 0x2c030ca8 | DSI_PSCTRL | PACKED_PS_24BIT_RGB888, WC=3240 |
| 0x14013020-0x38 | тайминги = 0 | VSA/VBP/VFP/HSA/HBP/HFP | Command mode — тайминги не нужны |
| 0x14013038 | 0x09600438 | DSI_SIZE_CON | 2400×1080 |
| 0x14013060 | 0x00000001 | DSI_CMDQ_SIZE | count=1 |
| 0x14013d00 | 0x002c3909 | DSI_CMDQ | DCS 0x2C (Write Memory Start) |

**Критические находки**:
- **DSI_BUSY = 1** — контроллер занят, но DSI_EN = 0 (выключен)
- **DSI_INTEN = 3** — драйвер записал в INTEN вместо CON_CTRL (ошибка п.1 из аудита)
- **Command mode** — подтверждено, video mode исключён
- **EXT_TE_EN = 1** — контроллер ждёт внешний TE от панели

## 7. Результаты экспериментов

### Эксперимент 1: Включить Layer 0

```
mw.l 0x14005044 0x10e0     # PITCH(0)
mw.l 0x1400502c 0x00000003 # SRC_CON = L0+L1
mw.l 0x1400500c 0x00400001 # OVL_EN + shadow reload
mw.l 0x14013d00 0x2c3909   # DSI CMDQ
mw.l 0x14013060 0x8001     # CMDQ_SIZE
mw.l 0x14013000 0x0        # DSI_START clear
mw.l 0x14013000 0x1        # DSI_START trigger
```

**Результат**: Красным не моргнул. Причина: video_sync() перетёр записи.

### Эксперимент 2: Включить DSI_EN

```
mw.l 0x14013010 0x01000002 # CON_CTRL |= DSI_EN
# DSI_BUSY не снимается (остаётся 0x80001016)
```

**Результат**: Без изменений. DSI_BUSY застрял.

### Эксперимент 3: Рабочий DSI trigger (2026-08-05)

**Открыто**: правильный порядок команд для command mode.

```
# Шаг 1: Сброс DSI (если BUSY=1)
mw.l 0x14013010 0x01000001; md.l 0x14013010 1; md.l 0x14013010 1; mw.l 0x14013010 0x01000001; md.l 0x1401300c 1

# Шаг 2: Загрузить CMDQ и отправить
mw.l 0x14013d00 0x2c3909; mw.l 0x14013060 0x0001; mw.l 0x14013010 0x01000002
```

**Результат**: ✅ **Текст консоли появился на экране!** Экран обновился, текст сдвинулся.

**Ключевые отличия от старого способа**:
- `CMDQ_SIZE = 0x0001` (без trigger-бита), а не `0x8001`
- DSI_EN устанавливается **после** CMDQ, а не перед
- Не нужен toggle `DSI_START`

### Эксперимент 4: 🟥 КРАСНЫЙ ЭКРАН ДОСТИГНУТ (2026-08-05, вторая сессия)

**Рабочая последовательность** (весь экран красный!):

```
# 1. dc off — mw.l пишет напрямую в память, OVL читает из памяти
dc off

# 2. Залить FB полностью (0x278d00 слов = 1080×2400×4 байт)
mw.l 0xfeabe000 0xffff0000 0x278d00

# 3. Сброс DSI (обязателен, если BUSY=1 в 0x1401300c bit 31)
mw.l 0x14013010 0x01000001; md.l 0x14013010 1; md.l 0x14013010 1; mw.l 0x14013010 0x01000001; md.l 0x1401300c 1
# → BUSY снимается: 0x80001016 → 0x00001016

# 4. Триггер кадра (CMDQ 0x2C + DSI_EN)
mw.l 0x14013d00 0x2c3909; mw.l 0x14013060 0x0001; mw.l 0x14013010 0x01000002
```

**Результат**: ✅ **Весь экран КРАСНЫЙ** (заливка 0xffff0000).
Артефакт: чёрная 1-пиксельная горизонтальная полоса на ~1/3 снизу — вероятно tearing-шов (нет синхронизации с TE).

### Эксперимент 5: ✅ ЗЕЛЁНЫЙ ЭКРАН — модель «1 кадр = 1 сброс» подтверждена

Повтор эксперимента 4, но со сбросом перед триггером (BUSY был застрявшим):

```
mw.l 0xfeabe000 0xff00ff00 0x278d00           # залить зелёным
mw.l 0x14013010 0x01000001; md.l 0x14013010 1; md.l 0x14013010 1; mw.l 0x14013010 0x01000001; md.l 0x1401300c 1   # сброс DSI
mw.l 0x14013d00 0x2c3909; mw.l 0x14013060 0x0001; mw.l 0x14013010 0x01000002   # CMDQ + DSI_EN
```

**Результат**: ✅ **Весь экран ЗЕЛЁНЫЙ**.

**МОДЕЛЬ ПОДТВЕРЖДЕНА**: каждый кадр = сброс DSI (CON_CTRL bit0, ×2 с задержкой) → CMDQ 0x2C → CMDQ_SIZE=0x0001 → DSI_EN=0x01000002. Без сброса кадр не уходит (BUSY=1).

**Подтверждение из ядра** (mtk_dsi.c:1027 `mtk_dsi_wait_for_idle`): при таймауте ожидания !BUSY ядро делает ровно то же — `mtk_dsi_enable()` + `mtk_dsi_reset_engine()` (toggle DSI_RESET bit0 CON_CTRL), затем повторная отправка.

**Расшифровка DSI_INTSTA = 0x80001016** (0x1401300c):
- bit 31 = DSI_BUSY
- bit 1 = CMD_DONE — команда отправлена
- bit 2 = TE_RDY — внутренний TE готов
- bit 4 = EXT_TE_RDY — **внешний TE от панели приходит** ✓

**Что НЕ работает**:
- **Toggle DSI_START (0x0 → 0x1) без CMDQ** (LK-способ FUN_0003f1bc) → экран остаётся чёрным
- **Повторный CMDQ+DSI_EN без сброса** при BUSY=1 → без изменений, BUSY не снимается (0x80001016)
- Заливка зелёным + триггер после успешного красного → **без изменений** (BUSY=1 после первого успешного кадра)

**Ключевой инсайт**: после каждого успешного кадра BUSY возвращается и висит (0x80001016). Следующий кадр требует сброса DSI (шаг 3) заново. Один кадр за сброс.

## 8. Ключевые выводы

1. **Драйвер mtk_disp_g99 мешает ручным экспериментам** — video_sync() вызывается на каждый символ shell
2. **Layer 1 включён LK, Layer 0 выключен** — драйвер настраивает не тот слой
3. **DSI_BUSY застрял** — контроллер в странном состоянии (выключен, но BUSY=1)
4. **Command mode подтверждён** — video mode исключён (MODE_CTRL=0)
5. **Клоки и питание в порядке** — LK оставил всё включённым
6. **Рабочий DSI trigger найден** — CMDQ → CMDQ_SIZE(0x0001) → DSI_EN(0x01000002)
7. **Bit 24 в CON обязателен** — без него DSI_EN не работает
8. **DSI_EN не держится** — это нормально для command mode (автоочистка после отправки)

## 9. Рекомендации

### Немедленно
1. **Убрать vidconsole из stdout** перед ручными экспериментами:
   ```
   setenv stdout serial,usbacm
   setenv stderr serial,usbacm
   ```

2. **Использовать рабочую последовательность DSI trigger**:
   ```
   # Сброс DSI (если BUSY=1)
   mw.l 0x14013010 0x01000001; md.l 0x14013010 1; md.l 0x14013010 1; mw.l 0x14013010 0x01000001; md.l 0x1401300c 1
   
   # Отправить DSI trigger
   mw.l 0x14013d00 0x2c3909; mw.l 0x14013060 0x0001; mw.l 0x14013010 0x01000002
   ```

### Для драйвера
1. **Исправить запись DSI** — писать в `CON_CTRL (+0x010)`, а не в `INTEN (+0x008)`
2. **Исправить ожидание BUSY** — ждать бит 31 (`DSI_BUSY`), а не бит 0 (`LPRX_RD_RDY`)
3. **Включить Layer 0** — SRC_CON должен быть `0x3` (L0+L1), а не `0x2` (только L1)
4. **Убрать реинит из video_sync()** — не переконфигурировать пайплайн на каждый кадр
5. **Исправить DSI trigger** — использовать `CMDQ_SIZE = 0x0001` + `DSI_EN`, а не `0x8001` + toggle

### Долгосрочно
1. **FB как non-cached** — убрать `flush_dcache_range()` из video_sync()
2. **damage-based обновление** — использовать `CONFIG_VIDEO_DAMAGE` для частичного обновления
