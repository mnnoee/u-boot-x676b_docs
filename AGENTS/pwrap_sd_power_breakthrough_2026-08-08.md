# PWRAP ОЖИЛ В U-BOOT! SD-питание включено (2026-08-08) — ПРОРЫВ

**Статус:** PWRAP полностью рабочий в U-Boot! SWCID читается (0x6610),
регуляторы SD пишутся и подтверждены чтением. MSDC1 физически видит карту
(CDSTS=1), но `mmc info` пока молчит — карта не отвечает на инициализацию.

## 🎯 ГЛАВНЫЕ ОТКРЫТИЯ (два условия для живого pwrap)

### 1. IFRAO0 (SPI-клоки pwrap) ВЫКЛЮЧЕНЫ после холодного старта!
Прелоадер при холодном старте инициализирует pwrap (INIT_DONE2=1),
но **НЕ включает SPI-клоки** (ifrao pmic_ap/pmic_tmr):
```
md.l 0x10001090 1   →   00000000   (!!! было 0 после холодного старта)
```
В сессии 1 (когда всё работало) клоки оставались включёнными — поэтому
работало. Включение: `mw.l 0x10001080 3` (SET: pmic_tmr=бит0, pmic_ap=бит1).

### 2. Запись CMD в WACS2 БЕЗ SPI-клоков = необратимая «смерть» pwrap
Если не включить IFRAO0 перед записью CMD — блок умирает (все регистры 0x0),
оживает только после холодной перезагрузки. Это объясняет все прошлые сессии!

### 3. UPD-строб (только для тёплого рестарта)
После тёплого рестарта (fastboot/`reset`) pwrap вообще мёртв (0x8441 константа
везде). Оживляет: `mw.l 0x10000008 4` (бит 2 = UPD для CLK_CFG_8,
mux pwrap_ulposc_sel). После холодного старта UPD не нужен.

### ⚠️ ИСПРАВЛЕНИЕ ОШИБКИ старого дока (pwrap_wacs2_live_debug_2026-08-06.md)
Там написано «0x8441 → INIT_DONE1=1» и я потом ошибочно решил, что бит 15 НЕ
установлен. **ВЕРНО: 0x8441 = 0x8000+0x400+0x40+0x1 → бит 15 (INIT_DONE1)=1!**
Т.е. 0x8441 = живое состояние: INIT_DONE1=1, FSM=0 (IDLE). Блок был жив всё
это время; умирал только от записи CMD без SPI-клоков.

## ✅ ПОЛНЫЙ РАБОЧИЙ ПРОТОКОЛ (проверен на холодном старте)

### Шаг 1 — Включить SPI-клоки (ОБЯЗАТЕЛЬНО, первым!)
```
mw.l 0x10001080 3      # IFRAO0 SET: pmic_tmr(0) + pmic_ap(1)
md.l 0x10001090 1      # проверить: 00000003
```

### Шаг 2 — Проверить живость (чтение, без записей!)
```
md.l 0x10026000 2      # INIT_DONE2 = 1 (прелоадер инициализировал)
md.l 0x100268A8 1      # 0x00008441: INIT_DONE1=1, FSM[3:1]=0 → IDLE
```

### Шаг 3 — Чтение PMIC (read16, ARB)
```
mw.l 0x10026880 0xA     # CMD = адрес (0xA = SWCID; адрес КАК ЕСТЬ, без >>1)
md.l 0x10026894 1       # SWINF_2_RDATA → 0x00006610 (SWCID MT6366 ✓)
mw.l 0x100268A4 1       # VLDCLR — ОБЯЗАТЕЛЬНО после чтения!
```

### Шаг 4 — Запись PMIC (write16, ARB)
```
mw.l 0x10026884 0x0400  # WDATA = значение
mw.l 0x10026880 0x20001E4C  # CMD = BIT(29) | адрес
```

### Шаг 5 — Читать обратно С ОЖИДАНИЕМ
⚠️ Данные приходят СО СДВИГОМ НА 1 ТРАНЗАКЦИЮ при пакетном чтении
(читается результат ПРЕДЫДУЩЕГО CMD — RDATA не очищается VLDCLR, а
обновляется к моменту следующего чтения). Надёжно: CMD → пауза → RDATA → VLDCLR.

## 💡 SD-ПИТАНИЕ ВКЛЮЧЕНО (подтверждено чтением обратно!)

| Регистр | Значение | Назначение |
|---|---|---|
| 0x1E48 (VMCH volt) | 0x0200 | 2.9V ([10:8]=2) |
| 0x1E4C (VMC volt) | 0x0400 | 1.8V ([11:8]=4) |
| 0x1CD8 (VMCH en) | 0x0001 | включён |
| 0x1CC4 (VMC en) | 0x0001 | включён |

Все значения совпали с Android-дампом (pwrap_pmic_regs_android_dump_2026-08-06.txt:
1cc4: 0001, 1cd8: 0001, 1e48: 0200, 1e4c: 0400). Питание реально подано!

## 📊 MSDC1 (0x11240000) — карта ВИДНА физически

```
md.l 0x11240000 8 →
11240000: 0200119b   # MSDC_CFG: бит8 CKE=1 (клок), бит24 MODE, PIO
11240004: 00000000   # MSDC_IOCON
11240008: 00010002   # MSDC_PS: бит1 CDSTS=1 (КАРТА ВСТАВЛЕНА!), бит16 DAT0=1 (в контакте)
11240010: 0000d700   # MSDC_INT
```
MSDC_PS.CDSTS (бит 1) = 1 → карта детектирована контроллером!

## ❌ НЕ РЕШЕНО: `mmc info` молчит

- `mmc list` → `mmc@11240000: 0` (единственный mmc, eMMC 0x11230000 НЕ описан в dts!)
- `mmc dev 0` / `mmc rescan` / `mmc info` → НИЧЕГО не выводят (не «Card did not
  respond», просто тишина) — даже «mmc0 is current device» не печатается!
- Это странно: `do_mmc_dev` печатает «mmcX is current device» при успехе.
  Молчание = init_mmc_device вернул NULL или команда оборвана.
- DTS: sdhc2: mmc@11240000, compatible "mediatek,mt8183-mmc",
  builtin-cd = <0>, vmmc/vqmmc = regulator-fixed always-on (ФИКТИВНЫЕ —
  U-Boot сам НЕ умеет включать реальный VMCH/VMC через pwrap, мы включили руками).
- Ошибка «TX/RX FIFO non-empty before start of IO. Reset» при mmc rescan —
  драйвер сам сбрасывает (msdc_start_command), не фатально.
- MSDC1 pad_tune0=0x403c0007, pad_tune1=0xffe64309 уже прописаны в драйвере
  (mtk-sd.c init_hw, MT6789-ветка).

### Гипотезы, почему карта не инициализируется:
1. **Pinctrl MSDC1 не работает в U-Boot** (pinmux 0x4901/0x4a01/0x4b01/0x4c01/
   0x4801 cmd-dat, 0x4701 clk — GPIO71-76). Если пины не переключены на MSDC —
   карта не ответит. Проверить: есть ли DM pinctrl для MT6789 в U-Boot.
2. Напряжение/сигналы — проверить физически (мультиметр на 1-й пин?).
3. init_mmc_device молча падает (NULL) — включить CONFIG_MMC_DEBUG и смотреть.
4. Клоки MSDC1 (CLK_TOP_MSDC30_1_SEL, IFRAO_MSDC1, IFRAO_MSDC1_SRC) — проверить,
   что драйвер их включил (md.l 0x10000090 — mux; IFRAO0 биты MSDC1).

## 🔧 Порядок при следующей работе (после перезагрузки)
1. `mw.l 0x10001080 3` — SPI-клоки (иначе CMD убьёт pwrap!)
2. Проверить pwrap жив (INIT_DONE2=1, WACS2_RDATA=0x8441)
3. Если после тёплого рестарта: ещё и `mw.l 0x10000008 4` (UPD) ДО проверки
4. SD-питание уже включено прелоадером/нами — но при новом старте проверить
   readback 0x1CD8/0x1CC4 (если 0 — включить заново по протоколу выше)
5. `mmc dev 0` → если молчит, копать pinctrl/MMC_DEBUG
