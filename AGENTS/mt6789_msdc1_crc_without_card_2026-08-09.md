# MSDC1: RSPCRCERR без карты — контроллер ловит мусор на CMD-линии

Дата: 2026-08-09. Сессия: v214 прошит, консоль `/dev/ttyACM0` (921600), утилита `uart_cmd.py` вместо MCP.

## Контекст
- v214 (Android-live регистры 1:1) всё ещё даёт RSPCRCERR (int=0x480) на CMD8/CMD55 при вставленной карте (ранний лог).
- Пользователь вынул карту. Вопрос: общается ли контроллер с картой, появляется ли CRC без карты?

## Ключевые факты

### 1. U-Boot упирается в CD и не шлёт команды без карты
- `mmc_init()` в `u-boot/drivers/mmc/mmc.c:3048-3063`: `no_card = mmc_getcd(mmc) == 0` → `"MMC: no card present"` → `return -ENOMEDIUM` — МОЛЧА (log_err подавлен), `mmc dev 0` ничего не печатает.
- Обход: слать команды контроллеру вручную через консоль `mw.l` (прямые записи в регистры).

### 2. Смещения регистров в нашем U-Boot mtk-sd.c (struct mtk_sd_regs, mtk-sd.c:243+)
```
0x00 msdc_cfg     0x08 msdc_ps     0x0C msdc_int     0x10 msdc_inten
0x14 msdc_fifocs  0x30 sdc_cfg     0x34 sdc_cmd      0x38 sdc_arg
0x3C sdc_sts      0x40 sdc_resp[0] 0x64 sdc_adv_cfg0 0x70 emmc_cfg0
```
- **ВАЖНО: MSDC_PS = 0x08, а НЕ 0x34!** (в ранней сессии 0x34 ошибочно читали как PS; 0x34 = SDC_CMD — там висел залипший rawcmd 0xb7 от CMD55).
- Маски INT (u-boot): bit8=CMDRDY, bit9=CMDTMO, bit10=RSPCRCERR, bit12=XFER_COMPL, bit14=DATTMO, bit15=DATCRCERR, bit3-5=ACMD*. Бит7 не определён (в GKI = SDIOIRQ).
- W1C: `mw.l 0x1124000C 0xFFFFFFFF` очищает INT.

### 3. Эксперимент: CMD8 БЕЗ карты (линии пустые, DAT0=0, PS=0x2)
- `mw.l 0x11240038 0x1AA` (SDC_ARG) + `mw.l 0x11240034 0x88` (rawcmd CMD8) →
  **INT = 0x400 (RSPCRCERR)** — стабильно, дважды. RSP[0]=0 (ответ не защёлкнут). FIFOCS=0x7c.
- Контроль: CMD0 (`mw.l 0x11240034 0x0`) → **INT = 0x100 (CMDRDY)** — чисто, без CRC.
- С вставленной картой (ранний лог v214): CMD8/CMD55 → **int=0x480** = 0x400 + бит7(0x80).
  Бит7 (0x80) появляется ТОЛЬКО с картой.

### 4. Вывод
- **RSPCRCERR НЕ доказывает, что карта отвечает**: контроллер выдаёт CRCERR даже на пустых/подтянутых линиях CMD — приёмник «принимает» мусор с неверной CRC.
- CMD0 (без ожидания ответа) проходит чисто → контроллер и тактирование работают.
- Значит проблема глубже: приёмный тракт CMD-ответа (окно семплирования/синхронизация приёма), а не сама карта.
- Бит7 с картой — реальная реакция карты на линии (DAT1 IRQ/данные), сигнал есть, но принимается искажённым.

## Новое отличие vs Android live: MSDC_CFG
| Регистр | Наш U-Boot (100 кГц init) | Android live (48 МГц DDR50) |
|---|---|---|
| 0x00 MSDC_CFG | 0x0201E09B | 0x35651729 |
- Совпадают: CKMOD (bits 8-9 = 0b10 SDR), bit16 (PIO), bit20, bit12-13.
- У нас 0, в Android 1: **bit8 (CKSTB)**, **bit5**, **bit14**, bit21-22, bit26, bit28-29, div (0x9B vs 0x29).
- У нас 1, в Android 0: bit1, bit4, bit7, bit9-11, bit17-19, bit25.
- Примечание: форматы div могут не совпадать из-за разных тактов (100 кГц vs 48 МГц) — для сравнения приёмника важны биты 5/8/14.

## Что ещё выяснено по CD (из доков и live)
- CDSTS (PS bit1) = 1 ВСЕГДА (и при вставленной, и при вынутой карте, и в Android live 0x01000002) — аппаратный CD-датчик слота не работает/не подключён. Android CD через GPIO7 (cd-gpios), не через CDSTS.
- Реальный индикатор карты: **DAT0 = PS bit16**: 1 = карта в контакте, 0 = нет.
- GPIO7: `gpio input 7` → 1 = карта есть, 0 = нет (active high) — работает.
- В начале сессии (карта вставлена): gpio7=1, DAT0=1. После вынимания: gpio7=0, DAT0=0.
